01 / ORIGIN · FROM A REAL BEHAVIOR

朋友转来的一篇帖子，
成了这个产品的起点。

THE POST THAT STARTED IT

《把想买的东西
发给朋友走审批》
“你觉得我该买吗？”

我注意到一种已经存在的消费行为：当一个人看到想买、但又没有完全确定的东西时，有时会把商品链接发给熟悉自己的朋友，问一句：“你觉得值得买吗？”

OBSERVATION

这个行为本身已经存在。用户并不是缺少一个替自己做决定的人，而是在寻找一个外部视角。

我开始思考：如果把一次发生在聊天里的消费讨论，变成一个有开始、有反馈、有结果的结构化流程，会发生什么？

BEFORE THE PRODUCT

一次消费决定，
原本发生在聊天里。

  1. 看到一个想买的东西
  2. 有点心动，但又不完全确定
  3. 把链接发给朋友
    “你觉得值得买吗？”
  4. 朋友提供另一种意见
  5. 最后还是自己决定

原来的行为已经存在。
它散落在聊天中，没有留下完整的消费决策过程。

02 / PROBLEM

THE FRICTION

想买的，
不一定值得买。

TARGET USER / DEFINED BY BEHAVIOR

那些已经产生购买欲，
但在真正付款之前，
仍愿意重新想一次的人。

我没有用年龄、职业或收入定义用户，而是用消费发生前的行为状态定义他们。

在我观察到的这些场景里，真正的问题不是用户完全不知道要不要买。

从“有点心动”到“直接付款”之间，往往缺少一个主动停下来重新审视的时刻。缺的不是答案，而是一次暂停。

PRODUCT HYPOTHESIS

如果付款之前，用户需要先把购买理由说出来，并听到一个来自朋友的外部视角，是否会更愿意重新审视这次消费？

This was the hypothesis I wanted to test.
这不是结论，而是我最初想验证的产品假设。

03 / PRODUCT INSIGHT

PRODUCT INSIGHT

问题不是买不买。
而是：少了一次
停下来的机会。

  1. 冲动消费
  2. 「真要买吗？」
  3. 朋友反馈
  4. 重新思考
  5. 自己决定

因此，我没有把产品设计成一个替用户判断“该不该买”的工具。它只负责创造一次：说明理由 → 获得外部视角 → 重新思考的机会。最终决定始终属于用户自己。

PRODUCT PRINCIPLES

第一版的取舍，
来自三个原则。

它们决定了 MVP 应该做什么，也决定了它不应该做什么。

01

DON'T DECIDE FOR THE USER

不替用户做决定

02

CREATE A PAUSE

在付款之前制造一次暂停

03

BRING IN AN EXTERNAL VIEW

让熟悉用户的人提供另一种视角

NOT IN THE MVP

不做 AI 自动判断“该不该买” · 不做强制消费限制 · 不做复杂预算管理 · 不替用户完成最终选择

第一版只验证一个核心假设：在付款前加入“说明 → 朋友反馈 → 再决定”，是否有人愿意使用。

MVP CORE FLOW · THE FIRST VERSION

MVP GOAL

01 / EXPRESS

把“我想买”
说清楚。

先写下商品、价格和购买理由。

把一个模糊的「好想买」，变成一个可以被讨论的问题。

02 / ASK

找一个熟悉你的人。

把这次消费申请分享给朋友。

不是继续说服自己，而是主动引入一个外部视角。

03 / PERSPECTIVE

听听朋友怎么说。

朋友可以批准、驳回，或者建议冷静一下。

好友给出的，是消费意见，不是替用户完成最终决定。

04 / YOU DECIDE

听完了，
最后还是你决定。

选择「不买了」或「还是买了」。

产品负责制造一次暂停，但不拿走用户的决定权。

FROM ONE-OFF TO ONGOING

一个人犹豫，
一群人帮你冷静。

一开始，产品解决的是一次性的消费犹豫。
但真实使用里，很多人并不是只问一次朋友。

他们会反复问同一群熟人：
这个要不要买？有没有平替？这次该不该忍住？

于是，一次性朋友反馈，
开始延伸成固定熟人长期参与的钱包小组。

一次性朋友反馈

  1. 发起一次申请
  2. 分享给朋友
  3. 收到几条反馈
  4. 做出决定

钱包小组

  1. 先有固定熟人关系
  2. 下次直接在组里发起
  3. 多人持续参与
  4. 形成长期记录

06 / WALLET GROUP

WHY WALLET GROUP

不是每次都
重新找人。

当用户一次次把消费申请发给同一群朋友时，
产品就不再只是“一次找人帮我看看”，
而是逐渐形成了一种长期存在的消费决策关系。

钱包小组不是更多人替你决定，
而是把“下次再问谁”这件事固定下来。

01 / FIX THE PEOPLE

先把“劝你的人”
固定下来。

创建或加入钱包小组，
把那些本来就会互相劝消费的熟人留在同一个地方。

这样下一次犹豫时，
不用重新找人、重新解释、重新建立上下文。

从一次分享，变成固定关系。

02 / ASK INSIDE THE GROUP

下次想买，
他们还在。

进入小组后，用户可以直接在这个关系里
继续发起新的消费申请。

“帮我看看”不再是临时分享，
而变成一种长期存在的协作方式。

不是重新邀请一遍朋友，
而是在已有关系里继续发起。

03 / ONGOING PARTICIPATION

它不会在一次决定后
立刻消失。

成员不仅能持续看到新的消费申请，
也能看到这个月的花钱状态、最近发生的记录。

这不再只是一次审批，
而是一段长期存在的消费协作关系。

一次求助，变成持续参与。

04 / YOU STILL DECIDE

大家都能劝，
但最后还是你决定。

小组成员会从不同角度给出意见：
可以买、别买、再忍忍。

朋友提供外部视角，
最终决定仍然属于申请人自己。

多人参与，不等于替你做决定。

05 / USER-DRIVEN ITERATION

产品不是上线以后
才完成。

它是在被使用以后，
才开始变得具体。

MVP 上线后，我建立了真实用户反馈渠道。我没有直接把每一条反馈当成需求：先判断用户真正遇到的问题、它是否影响核心流程，以及是否值得进入下一次迭代。

HOW I PRIORITIZED

CORE FLOW IMPACT 是否影响完成一次消费决策？　FREQUENCY 是否被反复遇到？　USER VALUE 是否改善理解、参与或决策体验？　COST / RISK 现在解决是否值得、是否破坏原有逻辑？

不是所有反馈都会直接变成功能。

CASE 01 · HISTORY & VISIBILITY

CASE 01 · DECISION DOESN'T END THE STORY

决定之后，
这条申请就结束了吗？

“没结束也能看到其他人的评论吗？”

“决定以后，这条申请就结束了吗？”

WHAT I FOUND

用户还想回看商品信息、朋友意见和最终决定。

PRODUCT JUDGEMENT

消费决定不是一次性动作，而是一段有回顾价值的过程。

WHAT CHANGED

增加历史记录；完成后的申请仍可查看商品信息、朋友意见和最终决定。

从“完成一次审批”，
变成“留下一个决策记录”。

CASE 02 · VIEWING ≠ VOTING

想看看大家怎么说，
不代表我现在就想表态。

“不审核的人也能看到其他人提的意见。”
USER SAID

我不一定要马上表态，但我想先理解这里正在发生什么。

WHAT I FOUND

原来的设计把“查看意见”和“参与审批”绑定在一起。但参与讨论，并不等于必须立即表态。

PRODUCT JUDGEMENT

“查看”和“做决定”应该是两个不同动作。

WHAT CHANGED

重新整理待审批、查看大家意见与历史记录之间的关系，让用户不需要完成审批，也能理解当前讨论。

查看 → 理解 → 参与讨论 → 最终决定。
不是所有进入页面的人，都需要立即做决定。

OTHER USABILITY IMPROVEMENTS

让判断所需的信息，
真正可被使用。

IMAGE PREVIEW

修复商品图片无法打开的问题。

PRODUCT INFORMATION

优化商品信息展示，让朋友可以在判断前看清必要信息。

这些反馈修正了单次消费申请的体验。

08 / REFLECTION

WHAT I LEARNED

做完这个产品以后，
我更清楚哪些问题还没被回答。

01 / WHAT I LEARNED

用户反馈不等于需求。

真实用户说出来的往往只是表面问题；需要继续判断用户真正卡在哪里，以及该改功能还是产品结构。

好的迭代，不是不断加功能。

MVP 到 Wallet Group 的变化来自新的使用模式，而不是“想多做一点”。

真实数据比漂亮的故事更重要。

上线以后，才开始区分什么已经发生，什么只是我希望发生。

02 / WHAT HAS BEEN VALIDATED

目前已有真实产品行为支持：

  • 用户愿意发起消费申请
  • 朋友愿意参与消费讨论
  • 用户会完成自己的最终决定
  • Wallet Group 已产生真实创建、参与与意见行为
03 / WHAT IS STILL UNKNOWN

用户会不会重复回来使用？

还需要重复使用率、回访周期与再次发起申请比例。

Wallet Group 是否真的形成长期关系？

还不知道同一小组是否持续活跃、成员是否重复参与。

40.5% 的“不买了”有多少来自产品影响？

目前只能确认结果，不能证明没有产品时用户原本一定会购买。

04 / WHAT I WOULD TEST NEXT
  1. REPEAT USE重复发起申请用户占比、第二次使用间隔、用户生命周期
  2. RESPONSE SPEED发起申请到第一条反馈的时间，以及等待是否造成流失
  3. WALLET GROUP RETENTION小组重复申请数、活跃周期、重复参与成员比例
  4. DECISION QUALITY通过决定后反馈、用户自评或访谈理解是否帮助重新思考

我下一步真正想知道的不是：
有多少人打开了这个产品。
而是他们会不会在下一次犹豫时，再次回来。

每一个结论，都等待下一次验证。
这些问题还没有答案。所以，这个产品还值得继续被使用。
